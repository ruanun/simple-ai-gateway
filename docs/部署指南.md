# 部署指南

> 面向生产部署。首次上手请先看 [快速开始](快速开始.md)。

## 部署形态

| 形态 | 适用 | 依赖 |
| --- | --- | --- |
| 单实例（默认） | 绝大多数团队 | 无 —— 单二进制 + SQLite 单文件，限流/熔断/会话粘连走进程内存实现，功能不降级 |
| 多实例 | 高可用/水平扩容 | Redis（共享限流/熔断/粘连状态，Pub/Sub 广播路由表与价格缓存热更新）+ MySQL/PostgreSQL |

## 二进制部署

### 构建或下载

```bash
sh scripts/build.sh        # 前端 → 后端顺序构建，产出 ./server
# 或从 GitHub Releases 下载对应平台归档（Linux/macOS/Windows，tar.gz / zip）
```

> ⚠️ 从源码构建时必须**先构建前端**（`cd web && pnpm build`）：后端用 `//go:embed` 内嵌 `web/dist`，该目录不存在时编译直接失败。`scripts/build.sh` 已处理好顺序。

### 首次配置（必读）

**安全启动护栏**：`jwt.secret`、`security.channel_key_aes_key`、`admin.password` 三项若仍为内置默认值或留空，进程会**拒绝启动**（切断「默认部署即被接管」链路）。首次运行前先备好配置：

```bash
cp config.example.yaml config.yaml     # 模板已在仓库根

# 生成强随机凭证（Git Bash / Linux / macOS）：
openssl rand -hex 32       # → 填入 jwt.secret
openssl rand -hex 16       # → 填入 security.channel_key_aes_key（32 hex 字符 = 32 字节，AES-256）
openssl rand -base64 18    # → 填入 admin.password（首启播种后可在后台改密）
```

> 仓库根的 `config.yaml` 与 `config.local.yaml` 都已被 `.gitignore` 忽略（入库的只有模板 `config.example.yaml`），填了真凭证也不会被误提交。

Docker 部署同理：把填好的 `config.yaml` 挂进容器（见下方 Docker 小节）。

### 运行

```bash
./server -c config.yaml    # 不带 -c 时若当前目录存在 config.yaml 会自动加载
```

### systemd 示例

```ini
[Unit]
Description=Simple AI Gateway
After=network.target

[Service]
User=saig
WorkingDirectory=/opt/saig
ExecStart=/opt/saig/server -c /opt/saig/config.yaml
Restart=always
RestartSec=3
Environment=TZ=Asia/Shanghai

[Install]
WantedBy=multi-user.target
```

## 健康检查与指标

- `GET /healthz`（或 `/health`）：进程存活，不查依赖，适合 liveness。
- `GET /readyz`：DB / Redis（启用时）/ 审计存储都可用才 200，适合 readiness / 反代摘流。
- `GET /metrics`：Prometheus 文本指标（构建信息、依赖健康、今日请求/错误/token/费用/延迟、进程内存/goroutine）。只含聚合数字，不含渠道/账号/凭证拓扑；建议由内网 Prometheus 抓取或在前置反代加访问控制。

镜像已内置 `HEALTHCHECK`（默认探测 `/healthz`）；若修改 `server.port`，需同步调整容器 healthcheck。K8s 示例：

```yaml
livenessProbe:
  httpGet: { path: /healthz, port: 8080 }
readinessProbe:
  httpGet: { path: /readyz, port: 8080 }
```

## 备份与恢复

默认 SQLite 部署可直接用二进制自带的备份/恢复命令（**恢复前必须停止网关进程**）：

```bash
# 备份：一致性快照（VACUUM INTO）+ 本地审计目录 audit/
./server -c config.yaml --backup ./backups
# 产物：backups/saig-YYYYMMDD-HHMMSS.db + backups/audit/

# 恢复：接受备份目录或 .db 文件；会先保留一份 <dsn>.before-restore-<时间> 再替换
./server -c config.yaml --restore ./backups
```

MySQL / PostgreSQL 请使用数据库原生工具（`mysqldump` / `pg_dump`）做备份；S3 审计正文由对象存储的生命周期策略管理。恢复后启动网关会自动跑迁移。

## Docker 部署

```bash
# 先按上文「首次配置」备好 config.yaml（含三项必改凭证），再挂载运行：
docker run -d --name saig \
  -p 8080:8080 \
  -e TZ=Asia/Shanghai \
  -v saig-data:/app/data \
  -v ./config.yaml:/app/config.yaml:ro \
  ghcr.io/ruanun/simple-ai-gateway:latest
```

> Docker Hub 同步发布：`docker pull docker.io/ruanun/simple-ai-gateway:latest`；`docker run` 时把上面的 GHCR 镜像名替换掉即可。镜像由 `v*` tag 的 Release 流水线产出；若 `latest` 拉不到，请用源码或本地 Docker 构建。

> 镜像为多架构（`linux/amd64` + `linux/arm64`），ARM64 服务器（如 Oracle Ampere、64 位树莓派）直接 `docker pull` 即可，不必本地构建。

> 不挂载 `config.yaml`（或凭证仍为默认值）时，容器会因启动护栏立即退出——`docker logs saig` 可见拒启原因。

> **端口暴露面**：`-p 8080:8080` 会绑到 `0.0.0.0`，即容器直接对公网可达。已有前置反代（推荐）时用 `-p 127.0.0.1:8080:8080` 只绑回环——`docker-compose.yml` 默认就是这个值。

> **数据目录用 named volume（`-v saig-data:/app/data`）而非 bind mount**：bind mount 会沿用宿主目录的属主、覆盖镜像内的属主设置，而容器以非 root 运行，宿主目录属主不对时数据库无法写入。确需 bind mount 时先在宿主 `chown -R 1000:1000 <宿主目录>`；权限不对时进程会直接报出进程 uid/gid、目录属主与修复命令，照做即可。

> **TZ 必须按部署地设置**：令牌日成本限额与用量聚合按本地日期切日，容器默认 UTC 会导致切日边界偏移 8 小时。

### docker-compose

仓库根有 `docker-compose.yml`（本地构建镜像，数据落 named volume）。默认**注释**了 `./config.yaml:/app/config.yaml:ro` 挂载行；先取消注释，否则容器会用内置默认凭证启动并被启动护栏拒绝：

```bash
# 确认已备好 config.yaml，并已取消 compose 里的 config 挂载注释
docker compose up -d
```

端口默认只绑回环（`127.0.0.1:8080:8080`），配合前置反代使用；需要容器直接对外时把该行改回 `"8080:8080"`。

多实例部署时解开 compose 内的 redis 块，并在挂载的 config.yaml 中开启 `redis.enabled`。

> **自建镜像想带上版本信息，用 `sh scripts/docker-build.sh` 代替 `docker compose build`。**
> `.dockerignore` 排除了 `.git`，镜像内无法从 VCS 戳记回退版本元数据，只能靠 ldflags 注入；
> 而 compose 不会自己去跑 `git`，裸跑 `docker compose build` 会让启动横幅与 `--version`
> 全是 `version=dev commit=unknown built=unknown`，线上跑的是哪份代码就核对不出来。
> 该脚本自动取 git 短号（含未提交改动的 `-dirty` 标记）与当前 UTC 时刻再调 compose。
> 核对镜像版本：`docker compose run --rm saig --version`（不要重复写 `./server`，
> `ENTRYPOINT` 已是它，重复写会让 `--version` 不被解析而走正常启动流程）。
> 用 Release 流水线发布的 GHCR 镜像则无此问题，release 已注入完整元数据。

## 配置参考

> 下面只列常用项；熔断/重试、告警、请求日志异步写、会话 TTL、后台任务周期等完整可选块见仓库根 `config.example.yaml`。

```yaml
server:
  port: 8080                # 监听端口
  # trusted_proxies: ["127.0.0.1"]  # 可信反代 IP/CIDR；缺省空=只信 TCP 对端，不采信 X-Forwarded-For

database:
  driver: sqlite            # sqlite（默认）/ mysql / postgres
  dsn: data/saig.db         # SQLite 为文件路径；MySQL/PG 为标准连接串
  max_open_conns: 0         # 连接池：最大打开连接数（0 = 驱动默认）
  max_idle_conns: 0         # 连接池：最大空闲连接数
  conn_max_lifetime: 0      # 连接池：连接最大存活秒数

redis:                      # 可选。单实例无需开启（内存实现功能不降级）
  enabled: false
  addr: 127.0.0.1:6379
  password: ""
  db: 0

admin:
  username: admin           # 首次启动播种的超管账号
  password: "__CHANGE_ME__" # 【必改】仅首次播种生效，之后在后台改密；须 8~64 字符，留默认/占位符/空则拒启

jwt:
  secret: "__CHANGE_ME__"   # 【必改】管理后台 JWT 签名密钥，不少于 32 字节；留默认/占位符/空则拒启
  expire_hours: 24

security:
  apikey_prefix: sk-saig    # 业务令牌前缀
  channel_key_aes_key: "__CHANGE_ME_TO_16_24_OR_32_BYTES__"
  # 【必改】渠道上游 Key 的 AES 加密密钥，长度必须为 16/24/32 字节，否则进程拒绝启动。
  # 留默认/空同样拒启；一旦有数据后不可直接换（换了旧密文解不开），如需轮换用 tools/migrate-key 重加密。
  # login_rate_limit: 10    # 登录/注册匿名端点每 IP 每分钟次数；<=0 关闭
  # v1_auth_fail_limit: 30  # /v1 每 IP 每分钟鉴权失败上限，达限后该 IP 本分钟直接 429（不查库）；<=0 关闭
  # login_user_fail_limit: 5  # 同一用户名每分钟登录失败上限（跨 IP 合计，防分布式爆破），达限后该用户名本分钟 429；<=0 关闭
  # upstream_block_private: false  # 渠道出站是否拒绝回环/私网地址（防 SSRF 打内网）；渠道全是公网上游时建议开启。云元数据地址（169.254.x.x 等）始终拒绝
  # default_app_concurrency: 20  # 应用未设并发上限（0）时的同时在途请求上限，封顶配额并发超额；<=0 表示未设置的应用不限；单个应用设 -1 可单独放开
  # default_key_rpm: 600    # 令牌未设 RPM（0）时的兜底每分钟上限；<=0 表示未设 RPM 的令牌不限流；单个令牌设 -1 可单独放开
  # anthropic_official_hosts: ["api.anthropic.com"]  # Anthropic auto 鉴权分流官方域名单

audit:                      # 取证审计异步写（可选）
  buffer_size: 256
  max_body_bytes: 0         # 0 = 不截断（流式响应另有 64 MiB 在途硬上限，超出即截断并如实标记）
  workers: 4                # 后台写 worker 数（缺省 4）

storage:                    # 审计正文存储（可选，缺省 local）。正文不进数据库
  type: local               # local | s3；多实例必须 s3
  local:
    root: data/audit
  s3:
    endpoint: s3.amazonaws.com
    bucket: saig-audit      # 须预先创建
    region: us-east-1
    access_key: ""          # 留空走 IAM/环境变量凭证链
    secret_key: ""
    use_ssl: true
    path_style: false       # MinIO/自建通常 true
    prefix: ""

log:                        # 进程日志（详见下文「进程日志」一节）
  level: info               # debug / info / warn / error
  format: text              # text（人读）/ json（对接日志采集）
  output: stderr            # stderr / stdout / 文件路径
```

## 反向代理

置于 Nginx/Caddy 之后时，三件事必须做对：

1. **透传 `Host` 与 `X-Forwarded-Proto`** —— 保持请求原貌，便于日志排障。（OIDC 回调地址已改为在「系统设置」显式填写，不再依赖这两个头。）
2. **对 `/v1/*` 关闭响应缓冲** —— 避免 SSE 流式输出被代理攒包。

Nginx 示例：

```nginx
location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_http_version 1.1;
    proxy_buffering off;              # SSE 不攒包
    proxy_read_timeout 300s;          # 长流式响应不被掐断
    # HTTPS 站点建议加 HSTS（网关自身不发，因 TLS 在反代终结）；CSP/X-Frame-Options 等由网关统一下发，勿在此覆盖
    add_header Strict-Transport-Security "max-age=31536000" always;
}
```

Caddy 默认透传 `Host`/`X-Forwarded-*` 且不缓冲流式响应，`reverse_proxy 127.0.0.1:8080` 即可。

3. **在 `config.yaml` 填 `server.trusted_proxies`** —— 网关缺省只信 TCP 对端地址、忽略 `X-Forwarded-For`（否则任何调用方伪造该头就能改写请求日志/审计/操作日志里的 `client_ip`）。放在反代后面时对端地址永远是代理自己，登录限流会把全站用户挤进同一个桶，任何人每分钟打满 10 次登录请求即可让所有人无法登录。把代理的 IP/CIDR 填进去后才会采信转发头：

```yaml
server:
  trusted_proxies: ["127.0.0.1"]   # 反代与网关同机；多机部署填代理网段，如 10.0.0.0/8
```

写错（非 IP/CIDR）进程会在启动期拒启并提示 `server.trusted_proxies 配置非法`。

> ⚠️ `X-Forwarded-For` 必须用上面的**追加式** `$proxy_add_x_forwarded_for`：它把真实对端追加在最右，网关从右往左取第一个不可信地址，客户端伪造的前缀无效。若改成透传 `$http_x_forwarded_for`（不追加），客户端就能任意伪造 IP，绕过登录与 `/v1` 鉴权失败限流、污染日志里的 `client_ip`。

## 多实例部署

1. 数据库换 MySQL/PostgreSQL（SQLite 是单文件，不适合多实例共享）。
2. `redis.enabled: true`，各实例指向同一 Redis：
   - 限流（API Key / 渠道 RPM）、熔断（渠道/账号/代理）、会话粘连全局共享；
   - 管理端修改渠道/路由/价格后，经 Redis Pub/Sub 通知所有实例热重建路由表与价格缓存。
3. 负载均衡层对 `/v1/*` 建议不设过短的空闲超时（流式响应可能长时间无字节间隔）。
4. `storage.type: s3`，各实例指向同一个桶：审计正文按 `audit/YYYY/MM/DD/<request_id>/` 分层写入，任一实例的详情页都能回放。`local` 只写本机目录，多实例下无法跨节点读取。

## 进程日志

进程日志（启动/错误/熔断探测等运维事件）与业务面的**请求日志**（后台「请求日志」页、落库可查）是两回事，互不影响。

- `log.level`：`debug` / `info` / `warn` / `error`，缺省 `info`。设为 `debug` 时额外保留 gin 的调试路由表输出（开发场景）；其余级别自动切 gin release 模式，启动输出干净。
- `log.format`：`text`（人读，缺省）或 `json`（每行一个 JSON 对象，可直接被 Loki / ELK / Vector 等采集解析）。
- `log.output`：`stderr`（缺省）/ `stdout` / 文件路径。文件按 append 写入且**进程不做轮转**——容器部署用 Docker 日志驱动限额（如 `json-file` 的 `max-size`），裸机落文件配 logrotate（`copytruncate` 模式）。路径无法打开时回退 stderr 并提示，不会因此起不来。

**管理面请求可观测**：`/admin/*`（含 `/admin/login`）每个请求完成后记一行 `请求完成`（方法/路径/状态码/耗时/客户端 IP）；请求失败时另有一行 `请求失败`，带错误码与**具体失败原因**（如「上游返回状态码 404」）。两行共享同一 `request_id`，可直接串联。

- 级别：5xx 记 `ERROR`，401/403 记 `INFO`（令牌过期、越权探测属高频常态，避免噪音淹没真正的故障），其余 4xx 记 `WARN`。即 `log.level=warn` 也能看到全部服务端故障。
- 查询串单列 `query` 字段（非空才带），分页/筛选参数常常正是触发失败的输入；不并进 `path`，便于日志系统按 `path` 聚合。
- 前端渠道页 10s 一次的 `/admin/breaker/status` 轮询不记访问日志（该端点若失败仍记错误日志），避免刷屏。
- 业务面 `/v1` 不记访问日志——每次调用已落请求日志表并支持详情回放，再记一行是重复放大。

**异常时才打印上游地址**：正常调用不记（量太大），但派发失败（502/503 全候选失败）的日志会带 `upstreams` 字段，列出本次**实际打到过**的上游地址与账号，形如 `ch1(acc11)=https://a.example.com; ch2(acc22)=https://b.example.com`；同渠道账号多次重试自动去重，纯熔断/无账号（压根没出站）则不带该字段。对内取证串只有 `ch{id}(model)`，多渠道时答不出「到底连的哪台」，这个字段补的就是它。管理面拉取上游模型失败时同理，错误信息里直接列出试过的完整候选 URL。

> 上游地址只进**进程日志**：回给终端调用方的错误摘要按设计不含渠道 ID/地址/代理等内部拓扑，落库的取证串格式也保持冻结不变。

**按请求串联排障**：每个请求的响应头都带 `X-SAIG-Request-Id`，同一标识同时出现在进程日志的 `request_id` 字段、后台请求日志与审计记录中——拿到客户端报错里的 ID，三处都能直接检索到这次请求。管理面操作出错时，浏览器开发者工具的响应头里就有这个 ID，可直接拿去 `docker logs ... | grep <id>`。

## 审计正文存储

应用开启审计后，每次请求的原始请求体与上游响应体**不进数据库**，gzip 后写入 `storage` 配置的后端；数据库的 `audit_records` 只留对象 key 与取证元数据（原始大小、是否截断、原文 SHA-256）。打开请求日志详情时才去后端取一次，无权限角色不会触发读取。

- **local（默认）**：落 `storage.local.root`（缺省 `data/audit`，与 SQLite 同级），目录 0700、文件 0600，写入走临时文件 + rename 保证原子。备份时把该目录与数据库一起打包。
- **s3**：S3 兼容协议，覆盖 AWS S3、MinIO、Cloudflare R2、阿里云 OSS、腾讯云 COS。桶须预先创建，进程启动时探活一次，桶不存在或凭证错误直接拒启。`access_key` 留空时依次尝试 `AWS_*`/`MINIO_*` 环境变量、`~/.aws/credentials`、实例 IAM 角色。建议在桶上配置服务端加密；生命周期规则可作为「系统设置 → 审计清理」之外的兜底，但以网关的清理任务为准（它先删对象再删行，避免孤儿对象）。启动探活走 HEAD Bucket，AWS 上除 `s3:PutObject`/`s3:GetObject`/`s3:DeleteObject` 外还需 `s3:ListBucket`，最小权限策略漏掉它会在启动期报 `探测 S3 bucket 失败: Access Denied` 拒启。
- **写入失败语义**：审计是旁路，后端写失败只计数并记日志，不影响请求主链路——对象写入失败记 `WARN`（`审计请求体写入存储层失败` / `审计响应体写入存储层失败`），记录落库失败记 `ERROR`（`审计记录落库失败`，意味着元数据层出了问题，更值得告警）。
- **升级说明**：本版本起数据库迁移已收敛为单条 `0001_init_schema` 基线，不再维护逐版本增量迁移。旧部署库升级前请先备份，然后清空 `schema_migrations` 表（或重建数据库），再启动新版本；`0001` 会通过 AutoMigrate 补齐当前所有列/表。旧版的 `audit_blobs` / `audit_event_chunks` 表与 `audit_records.request_blob_id/response_blob_id` 列可手工删除，已不再使用。
- **切换后端不迁移**：把 `storage.type` 从 `local` 改为 `s3`（或反向）后，旧后端里已写入的正文不会自动搬迁——旧记录在详情页会显示空正文（进程日志有 `审计正文读取失败`），旧目录/桶里的对象成为孤儿需人工清理。切换前先跑一次「系统设置 → 审计清理」或接受旧正文不可回放。

## 数据与备份

- **SQLite**（默认）：备份整个 `data/` 目录（`saig.db` + `audit/` 审计正文）；建议停机或用 SQLite 在线备份，`audit/` 目录可直接打包。
- **MySQL/PG**：常规数据库备份策略；`storage.type: local` 时另需备份 `storage.local.root` 目录，`s3` 时由桶的版本化/跨区复制负责。
- 审计正文（存储层对象）与请求日志可在后台「系统设置」配置**超期自动清理**；审计清理会先删存储层对象再删记录行。

## 安全加固

上线前逐项确认（前三项现由**启动护栏强制**：不改则进程拒绝启动）：

- [ ] `admin.password` 已设为强随机值（默认 `sag12345` 会被拒启；首启播种后可在后台改密）
- [ ] `jwt.secret` 已替换为强随机值（默认值会被拒启）
- [ ] `security.channel_key_aes_key` 已替换（16/24/32 字节，默认值会被拒启），并妥善保管——丢失后已存渠道 Key 无法解密
- [ ] 外网入口走 HTTPS（反向代理终止 TLS）
- [ ] 容器端口不直接绑 `0.0.0.0`：compose 默认已是 `127.0.0.1:8080:8080`，`docker run` 同样建议 `-p 127.0.0.1:8080:8080`，公网入口交给反代
- [ ] 若管理面不需要暴露公网，在代理层对 `/admin`、`/login`、非 `/v1` 路径做 IP 白名单
- [ ] 按需在「系统设置」关闭使用方门户注册（默认建议关闭，由管理员建号）
- [ ] `TZ` 已按部署地设置（影响日成本限额与用量聚合切日）

## 从默认凭证迁移到强随机密钥

若曾以**内置默认凭证**启动过（库里已有渠道/账号等数据），补上强随机凭证后再启动会被护栏拦下——但**数据无需丢弃**：旧的账号上游 Key 密文是用「公开的内置默认 AES key」加密的，可自动重新加密到新 key。

> ⚠️ 仅适用于旧库用的是**默认 AES key** 的情况。若旧库用的是你自设、之后又**丢失**的 AES key，则密文无法恢复，只能在后台重录上游 Key。
>
> 若这次同时跨版本升级，先按上文「审计正文存储 · 升级说明」清空 `schema_migrations` 并让新版本跑一次 `0001` 基线，再执行本工具；否则旧库可能缺新列。

步骤（以 SQLite 为例）：

```bash
# 1. 先备份数据库
cp data/saig.db data/saig.db.bak

# 2. 准备 config.local.yaml（与 config.yaml 一样已被 .gitignore 忽略，密钥不进 git），填三项强随机凭证
cp config.example.yaml config.local.yaml
#   jwt.secret          → openssl rand -hex 32
#   channel_key_aes_key → openssl rand -hex 16   # 32 字节 => AES-256
#   admin.password      → openssl rand -base64 18

# 3. 运行迁移：用默认 key 解密、新 key 重新加密所有账号上游 Key，
#    并把仍是默认弱口令的 admin 重置为 config.admin.password
go run ./tools/migrate-key -c config.local.yaml
#   旧 key 非默认值时用 -old <旧key> 指定；不想动 admin 口令加 -reset-admin=false

# 4. 用新配置启动（配置在 config.local.yaml，须显式 -c；Windows 为 server.exe）
./server -c config.local.yaml
```

迁移全程事务包裹（失败自动回滚、可安全重跑），结束后会校验「所有账号均可用新 key 解密」。因为 `jwt.secret` 同时换新，旧登录令牌会因验签失败自动失效，之后用新的 `admin.password` 登录。
