# 快速开始

> 目标：10 分钟内跑通「启动网关 → 配置渠道 → 发出第一个请求」。
> 更完整的部署选项见 [部署指南](部署指南.md)，各功能页详解见 [使用手册](使用手册.md)。

## 1. 准备配置（必读）

启动前先备一份 `config.yaml`。**安全启动护栏**要求 `jwt.secret`、`security.channel_key_aes_key`、`admin.password` 三项必须是你自己的值——留默认或留空会**拒绝启动**：

```bash
cp config.example.yaml config.yaml     # 模板在仓库根
# 生成强随机值填进去（Git Bash / Linux / macOS）：
openssl rand -hex 32       # → jwt.secret
openssl rand -hex 16       # → security.channel_key_aes_key（32 hex 字符 = 32 字节）
openssl rand -base64 18    # → admin.password（首启播种，之后可后台改密）
```

## 2. 启动

三种方式任选其一：

**方式 A：二进制（推荐）**

从 GitHub Releases 下载对应平台的归档（tar.gz / zip，内含可执行文件与配置模板），或本地构建：

```bash
sh scripts/build.sh        # 先构建前端再编译后端，产出 ./server（Windows 为 server.exe）
./server -c config.yaml    # 默认监听 :8080（当前目录有 config.yaml 时可省略 -c）
```

**方式 B：Docker**

```bash
docker run -d --name saig \
  -p 8080:8080 \
  -e TZ=Asia/Shanghai \
  -v saig-data:/app/data \
  -v ./config.yaml:/app/config.yaml:ro \
  ghcr.io/ruanun/simple-ai-gateway:latest
```

> Docker Hub 同步发布：`docker.io/ruanun/simple-ai-gateway:latest`，参数与上面的 GHCR 命令相同。镜像与 Releases 归档由 `v*` tag 的 Release 流水线产出；若 `latest` 尚不可用，请用方式 A/C 本地构建。

> 上面 `-p 8080:8080` 会绑到 `0.0.0.0` 便于直接试用；正式部署请前置 HTTPS 反代并改为 `-p 127.0.0.1:8080:8080`（见 [部署指南 · 安全加固](部署指南.md#安全加固)）。数据目录建议保持 named volume（`saig-data`），换成 bind mount 需在宿主 `chown -R 1000:1000 <目录>`，否则容器内非 root 进程写不进数据库。

**方式 C：源码运行（需 Go 1.26+ 与 pnpm）**

```bash
cd web && pnpm install && pnpm build && cd ..   # 必须先构建前端（go:embed 依赖 web/dist）
go run ./cmd/server -c config.yaml
```

首次启动会自动建表，并按 `admin.password` 播种超级管理员 **`admin`**，数据默认落盘 `data/saig.db`（纯 Go SQLite，零外部依赖）。

## 3. 登录管理后台

浏览器打开 `http://localhost:8080`，落地页选「管理后台」，用 `admin` + 你在配置里设置的口令登录。

> ⚠️ 播种口令来自 config 明文，登录后建议在右上角再改一次密码；`jwt.secret` 与 AES 密钥已在启动前设好（否则进程起不来），详见 [部署指南 · 安全加固](部署指南.md#安全加固)。

## 4. 配置一条渠道

进入「渠道管理」→「新增渠道」：

| 字段 | 填什么 |
| --- | --- |
| 协议 | 上游是 OpenAI 兼容端点选 `OpenAI`，是 Anthropic 原生端点选 `Anthropic`。**一渠道一协议**，上游两种都提供时各建一条 |
| Base URL | 如 `https://api.openai.com/v1`、`https://dashscope.aliyuncs.com/compatible-mode/v1` |
| 上游 API Key | 创建渠道时自动生成一个默认账号存放此 Key（后续可在「密钥池」加更多密钥轮换） |

创建后在该渠道行内点「模型」，添加此渠道支持的真实模型名（如 `gpt-4o`、`qwen-plus`）。

## 5. 配置价格

**目标模型必须已配价格，否则请求返回 400。**

进入「价格管理」→ 点「从 models.dev 同步」自动匹配官方价；未匹配到的模型手动「配置价格」（单位：USD / 1M token，分 输入/输出/缓存 项）。

## 6. 创建应用与令牌

1. 「应用管理」→ 新增应用（应用是**配额主体**，团队共享额度；配额填 0 表示不限）。
2. 「令牌管理」→ 新增令牌，归属到刚才的应用。令牌明文 `sk-saig-xxx` **仅显示一次**，立即保存。

## 7. 发出第一个请求

```bash
curl http://localhost:8080/v1/chat/completions \
  -H "Authorization: Bearer sk-saig-xxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{"model": "gpt-4o", "messages": [{"role": "user", "content": "你好"}]}'
```

返回正常即链路打通。「请求日志」页可看到这条请求的路由、耗时、token 与费用。

## 8. 接入常用工具

管理后台内置「接入文档」页，含 Claude Code / Codex CLI / Cursor 等工具的详细配置步骤与环境变量对照表。要点：

- **Claude Code**：走 `/v1/messages`（Anthropic 协议），`ANTHROPIC_BASE_URL` 填网关根地址（不带 `/v1`），目标模型须挂在 Anthropic 协议渠道上（或开启渠道「协议转换」由 OpenAI 渠道兜底）。
- **Codex CLI**：走 `/v1/responses`，配置 OpenAI 兼容端点即可。
- **通用 OpenAI SDK**：`base_url` 填 `http://<网关>/v1`，`api_key` 填 `sk-saig-xxx`。
