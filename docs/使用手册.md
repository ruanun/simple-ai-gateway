# 使用手册

> 面向网关管理员与使用方。部署与配置见 [部署指南](部署指南.md)，首次上手见 [快速开始](快速开始.md)。

## 核心概念

一次请求的完整链路：**鉴权 → 令牌治理 → 路由 → 会话粘连 → 派发 → 计费落库**。理解下面几个对象即可掌握全局：

| 对象 | 角色 |
| --- | --- |
| **渠道（Channel）** | 一个上游端点：协议（OpenAI / Anthropic，一渠道一协议）+ Base URL + 超时/优先级/权重/RPM/计费倍率 |
| **账号（Account，密钥池）** | 渠道下挂多把上游密钥，按优先级+权重+健康度轮换，账号级熔断；配合 IP 代理池实现「账号 + IP 双通道轮换」分摊限流与容灾 |
| **渠道模型** | 声明某渠道支持哪些真实模型，路由的依据 |
| **别名（Alias）** | 一个虚拟模型名路由到多条「渠道×真实模型」边：优先级=故障降级层级（大者先试），权重=同层加权随机 |
| **应用（App）** | **配额主体**：团队共享额度（USD），超限 402；可限定允许使用的渠道（渠道 ACL）与模型（模型白名单）、同时在途请求数（并发上限）；审计开关挂在应用上 |
| **令牌（API Key）** | 调用方凭证 `sk-saig-xxx`，归属某应用；可配模型映射/白名单/日成本上限/RPM |
| **价格（ModelPrice）** | 按「USD / 1M token」分项计价（输入/输出/缓存读/缓存写），支持按次计费；**渠道覆盖价 → 全局价** 两级解析，再乘渠道倍率 |

**协议与透传**：`/v1/chat/completions`、`/v1/messages`、`/v1/responses` 三主端点**入什么协议出什么协议**，只替换凭证 + 改写 model，tool_use / thinking / 流式 SSE 自动兼容。渠道开启「协议转换」后可作为异协议请求的兜底候选（chat↔messages 转换，恒排在同协议透传候选之后）。免费 token 计数端点：`/v1/messages/count_tokens`、`/v1/responses/input_tokens`（不计费，仍走鉴权/路由/熔断）。

**幂等**：非流式 `/v1` POST 可带 `Idempotency-Key: <唯一值>`。同 key 同请求体重放会直接返回缓存响应、不重复计费；同 key 不同请求体返回 409；处理中重试返回 409；流式请求不支持幂等（明确 400）。记录 24 小时过期。

**会话粘连**：同一会话自动路由到同一账号（吃上游 prompt cache），5 分钟滑动窗口；粘连账号不健康时自动逃逸重选。

## 管理后台

### 仪表盘

今日/累计 KPI（请求、Tokens、费用、缓存读、应用数）、按小时用量趋势（6h/24h/3天/7天）、模型用量排行。

### 接入文档

内置的客户端接入指南：Claude Code、Codex CLI、Cursor、通用 OpenAI/Anthropic SDK 的配置步骤、环境变量对照与常见坑，可直接发给使用方。

### 调试台

在后台直接对网关发起测试请求（选模型/令牌，看原始响应与 SSE 流），配渠道后先在这里对拍再给客户端用。

### 渠道管理

渠道的增删改查，行内操作包括：

- **密钥池**：加/停账号（上游 Key AES 加密存储）、绑定代理组、优先级与权重、健康状态；账号级最大并发 / RPM、凭证过期时间、临时停用、限流/过载冷却窗口。
- **错误透传**：渠道可开启「全候选失败时透传最后一个上游错误」——用上游状态码与已脱敏文案代替通用 502/503 摘要；直接打到上游的非重试错误本来就脱敏透传。
- **定价**：渠道覆盖价（只对本渠道生效，优先于全局价）。
- **模型**：本渠道支持的真实模型；也可从上游拉取——网关按 Base URL 推导候选端点依次尝试（含 `/v1/models`、已含版本段时的 `/models`，以及 Anthropic 兼容子路径剥离后回根域名的变体），拉不到时会给出上游状态码与响应正文便于排查。上游未开放模型列表接口时手动添加即可。未定价的模型数会红字提示并可一键跳转价格页。
- **编辑**：Base URL、超时、优先级/权重（跨渠道路由用）、最大重试、渠道 RPM、**计费倍率**（实际成本 = 有效价 × 倍率，适合按折扣采购的转售渠道）、**协议转换**开关、Anthropic 鉴权头风格（auto / x-api-key / bearer / both）、自定义请求头（鉴权头等受保护名会被网关忽略）。

### IP 代理池

代理条目（http / https / socks5）与代理组管理。账号绑定代理组后出站流量经代理轮换，代理级熔断自动跳过坏节点。

## 中英文切换

管理端顶栏、门户顶栏、登录页与落地页右上角有 `EN / 中文` 切换，语言保存在浏览器 localStorage。当前已迁移导航、登录、仪表盘、渠道/令牌/应用/价格/别名/日志/设置/渠道健康、门户、调试台、用量分析等主要页面；接入文档正文与部分长篇帮助文案仍为中文，未翻译文案自动回落中文。

## 渠道健康

「审计观测 → 渠道健康」按渠道聚合最近 7/14/30 天的请求数、错误数、错误率、加权平均延迟、首 Token 延迟与费用；错误率 ≥5% 标黄、≥10% 标红，便于先看异常渠道。数据来自 `usage_daily_channel`，低流量渠道仍由主动探测器补足熔断恢复。

### 别名路由

创建虚拟模型名（如 `smart`），添加路由边指向多条「渠道 × 真实模型」。优先级高的层先试（故障降级），同层按权重加权随机（负载均衡）。**计费按实际命中的真实模型价格**，不按别名名。

### 应用管理

配额主体。设置总额度（0 = 不限）、允许渠道（空 = 不限）、模型白名单（空 = 不限）、最大并发（0 = 按全局 `security.default_app_concurrency`，-1 = 不限）、归属使用方用户、审计开关；「趋势」看该应用的用量曲线。

> 对外服务时，**应用是管理员对租户的硬边界**：模型白名单与并发上限使用方在门户里改不了，对该应用下所有令牌（含使用方自建的）生效。令牌上的白名单/日成本只是使用方的自我约束，生效取两层交集。配额是软限额：请求前按预估在途预留、响应后按实际成本多退少补，并发上限把临界点的超额封在「并发数 × 单次成本」以内。

### 令牌管理

- **模型映射**：如 `gpt-4 → gpt-4o`，请求进来先改写模型名（映射结果贯穿路由/计费/日志）。
- **模型白名单**：改写后的模型不在名单内返回 403。
- **日成本上限**：当日累计费用超限返回 402，次日自动重置。
- **RPM 限流**、标签分类、按令牌查日志/趋势。
- 令牌明文仅创建时显示一次，库中只存哈希。

### 价格管理

全局官方价维护。「从 models.dev 同步」自动匹配主流模型官方价；支持 Token 分项计价与按次计费（如图像生成）。**目标模型未配价格时请求直接 400**，宁可拒绝也不漏计费。

### 使用方用户

管理端为使用方建号（可同时创建同名默认应用并设配额）、重置密码、启停、删除。使用方通过门户自助查看名下资源。

### 请求日志

每请求一条：模型、协议（含转换标记如 `anthropic→openai`）、渠道、应用、接口类型、会话 ID、状态、首字/总延迟、分项 Tokens、费用、是否流式、客户端 IP。支持渠道/应用/令牌/模型/接口类型/时间多维筛选。

**审计回放**：应用开启审计后，原始请求体与上游响应体异步写入存储层（本地目录或 S3，不进数据库、不阻塞请求链路），在日志详情中直接回放完整入参出参（含截断标记与全文 SHA-256 完整性哈希），请求头自动脱敏。满足合规取证需求，配合「系统设置」的超期清理控制体积。

### 操作日志

管理端谁在什么时候改了什么（渠道/价格/令牌等变更审计）。

### 用户管理

管理端 RBAC 三角色：

| 角色 | 权限 |
| --- | --- |
| `super` 超管 | 全部权限 |
| `ops` 运营 | 除「用户管理」「系统设置」外全部 |
| `viewer` 只读 | 仅查看 |

### 系统设置

- **审计清理 / 请求日志清理**：超期自动删除，控制库与存储层体积。
- **使用方门户**：注册开关（关闭时仅管理员建号）；注册人机验证（不启用 / 图形验证码 / Cloudflare Turnstile），开放注册时建议开启，防脚本批量注册刷默认配额。
- **OIDC 第三方登录**：为使用方门户配置通用 OIDC（issuer / client_id / client_secret / 按钮文案 / **回调地址**）。回调地址形如 `https://你的域名/portal/api/oidc/callback`，在此显式填写并在提供方登记同一地址（启用时必填，可点「填入当前地址」）；网关不再按请求的 `Host` 推导。登录流程启用 PKCE 与 nonce 校验，令牌经短时 HttpOnly cookie 交给门户页面，不出现在 URL 里。

## 使用方门户

使用方（拿 API Key 调用的人）的自助界面，与管理端完全隔离（独立登录态）。入口：落地页「使用方门户」或 `/portal/login`。

- **概览**：名下应用的配额、已用额度与状态。
- **我的令牌**：自助创建/停用自己应用下的令牌；被管理员停用的令牌（显示「管理员已停用」）无法自行启用，只能删除或联系管理员。
- **请求日志**：只看自己应用的调用记录。
- 登录方式：账号密码（管理员建号或开放注册时自助注册）、OIDC 第三方登录（若已配置）。

## 常见问题（按状态码）

| 现象 | 原因与处理 |
| --- | --- |
| `400` 模型未定价 | 目标真实模型（别名/映射后的）没配价格 → 价格管理页补价或点渠道行内红字提示跳转 |
| `401` | 令牌无效/已停用 |
| `402` | 应用配额用尽，或令牌日成本超限（次日重置）→ 应用管理调额度 |
| `403` | 令牌或应用的模型白名单不含该模型，或应用渠道 ACL 不含目标渠道 |
| `404` 模型不存在 | 路由表查不到该模型：渠道模型没加、别名没建，或模型挂错协议的渠道（如 Claude Code 请求的模型只挂在 OpenAI 渠道且未开协议转换） |
| `429` | 令牌 / 账号 / 渠道 RPM 限流，或应用同时在途请求数达到并发上限 |
| `502` / `503` | 候选渠道全部失败：有上游实际失败（含上游错误）为 502；全部未出站（熔断/无可用账号）为 503 + `Retry-After` → 看请求日志定位渠道，检查账号健康与上游可用性 |
| SSE 输出一卡一卡 | 反向代理没关缓冲 → `proxy_buffering off`（见部署指南） |
